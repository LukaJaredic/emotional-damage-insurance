# Testing

## Test Types

- Prefer integration tests for feature behavior.
- Use unit tests for important utilities and shared logic.
- Keep E2E tests for a small number of critical journeys.

Test what the user sees and does instead of internal hook calls.

## Commands

```bash
npm run test
npm run e2e
npm run e2e:headed
```

Do not run E2E tests while `npm run dev` is running. Playwright starts its own app and mock API servers.

## Test Setup

Useful files:

- `src/testing/setup.ts`
- `src/testing/test-utils.tsx`
- `src/testing/mocks/server.ts`
- `src/testing/mocks/handlers`

Global setup resets the DOM, mocks, mock database, MSW handlers, cookies, and query client after every test. Tests should not repeat this cleanup.

Persisted fixtures need `BaseEntity` fields. Use `testAuditFields` when building them and `clearAutogeneratedFields()` when comparing form payloads.

## Rendering The App

Use `renderApp()` when a test needs providers, routing, auth, permissions, or React Query.

```tsx
await renderApp(<UsersMasterPage />, {
  user: testUsers.admin,
  path: paths.users.path,
  url: paths.users.getHref(),
})
```

`renderApp()` creates and logs in the test user, sets the auth cookie, renders providers, and waits for the current-user query.

## Queries And Interactions

- Use `screen.getBy...` for content that is already present.
- Use `screen.findBy...` for content that appears after async work.
- Use `screen.queryBy...` when checking that content is absent.
- Use `within(...)` to scope checks to a row, card, or dialog.
- Use `waitFor(...)` when the assertion changes over time.
- Use `userEvent.setup()` for user interactions.
- Reuse helpers such as `selectOptions()` when available.

Prefer accessible labels and roles:

```tsx
await user.type(screen.getByLabelText('Email'), 'admin@example.com')
await user.click(screen.getByRole('button', { name: 'Login' }))
```

## Mock APIs With MSW

Integration tests should keep the real API hook, Axios client, React Query cache, and UI. Override the server response instead of mocking the hook or shared field.

```tsx
server.use(
  http.get(`${env.API_URL}/policy-holders`, () =>
    HttpResponse.json([policyHolder]),
  ),
)
```

This also applies to remote selects. Let the real `RemoteSelectField` request its options, then interact with it as a user would.

Capture request parameters or bodies inside an MSW handler when testing API input:

```tsx
server.use(
  http.post(`${env.API_URL}/policies`, async ({ request }) => {
    requests.push(await request.json())
    return HttpResponse.json(createdPolicy, { status: 201 })
  }),
)
```

Direct mocks are still useful for browser-only behavior such as forcing a desktop media query, or for a small child component used only to trigger a callback.

## Simple Rules

- Start with an integration test.
- Prefer MSW over mocking API hooks.
- Keep render helpers small.
- Trust global cleanup.
- Test permissions through visible behavior.
